 STEP 0 -- CLICK "SYNC NOW" FIRST. EVERY TIME.
===============================================================

In the project, open the GitHub connector settings and click the
SYNC NOW icon. Wait for it to finish. THEN start the chat.

THE SYNC IS MANUAL. IT DOES NOT HAPPEN ON ITS OWN.

Cloud never reads your repository. It reads a COPY that only
changes when you click that icon. Confirmed by Anthropic support
2026-08-12, including that there is no way to see how old the
copy is from inside a chat.

Skipping this is not a small mistake. On 2026-08-10 the copy
froze, and Cloud spent two days answering from a snapshot that
was two days and thirty commits behind -- confidently, and
looking exactly like correct answers. That is the whole reason
for the freshness stamp in step 1.

Rule: CLAUDE CODE PUSHES, THEN YOU CLICK SYNC NOW. Every push
that matters to Cloud. If you did not click it, Cloud has not
seen the work.

 WHY THIS FILE CHANGED ON 2026-08-12
---------------------------------------------------------------

It used to say: read ProjectDocs\_READ-FIRST-Briefing-*.md and
take the newest by the date in the filename.

CLOUD CANNOT DO THAT. It cannot list a folder and it cannot sort
one. With five briefings in ProjectDocs it searched by relevance,
took whichever ranked highest, and reported that as success. On
2026-08-12 it told Bill it could not find the current files at
all -- while every one of them was tracked and on origin/main.

The instruction was correct for Claude Code, which can glob, and
impossible for Cloud, which cannot. Nobody noticed the asymmetry
because the failure was silent: Cloud always found A briefing.

THE FIX: ProjectDocs/CURRENT.md. One filename that never changes,
listing the filenames that do. Cloud reads one name it was told
and gets valid pointers.

CURRENT.md IS GENERATED, NEVER TYPED -- by Tool2\Update-Current.ps1,
run at session end. A pointer kept by hand is the exact failure it
exists to prevent: 15 of 49 filename references in this project had
already gone dead. It refuses to write at all if any document is
missing, rather than publish a list with a hole in it.

WHY THE FRESHNESS STAMP, NOT THE PANTHER PHRASE (changed 2026-08-21):
this block used to ask Cloud to find the phrase "local account named
panther" in the briefing as a freshness discriminator. CURRENT.md now
opens with a generated stamp -- generation time, commit hash, commit
date, commit subject -- and that is strictly better. It cannot be
forgotten or drift the way a hand-placed phrase does, and it says
stale BY HOW MUCH, not merely stale or not. Reading the stamp IS
reading the sync date.

WHY THE PHRASE WAS RETIRED: a discriminator is worth only what its
string's uniqueness is worth. Measured 2026-08-12, "panther" alone
appeared 23 times across 14 files, including two where it was just
Bill's name on a header -- "Prepared for: Panther (William F. Burns
III)". The check had to ask for the whole phrase to be safe, and even
then it could only ever answer stale or not-stale. A commit hash is as
unique as a check can get, so the stamp replaced it.

The phrase "local account named panther" appears ONLY in documents
dated 2026-08-11 or later. That is what makes it a discriminator.

THE GENERAL RULE: a freshness check is only worth as much as the
uniqueness of the string it asks for. Before trusting one, grep the
whole tree for that string and confirm every hit is in a current
file. If any hit is old, the check can pass while being wrong.
